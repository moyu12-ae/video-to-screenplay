# v0.6 设计：演员表 / 术语表——唯一命名权威

状态：**动工中**（分支 `feat/cast-glossary-v0.6`，按 §10 的 P-1→P5 顺序推进，每步带前后对照证据）。
本文档先于代码定稿，是为了让"闸门先于功能"：任何一步没有对应的 §6 检查与 §13 反例测试，就不算完成。

来源是 2026-09-19 在《再见菈菈》第 2 话 35 秒切片上的实测翻车：
声学层诚实输出 5 个匿名簇（`name: null`、`characters_manifest: {}`），而写作者在没有证据的情况下
把 A1 命名为"茉里"——真值是金发青年；并且基于这个错误命名，写作者又擅自推翻了声学归属（把第 8、9
条改判给"奶奶"）。拼装阶段的 lint 当时**已经点名了三个编造的名字**，但只是告警，被忽略了。

这份文档要解决的不是"让模型更聪明地猜名字"，而是**把命名权从模型手里收回来，交给一次人审定 +
机器强制执行**。

实测样本（本文所有数字都出自这两次端到端实跑，非估算）：《再见菈菈》第 2 话
`06:07.9-06:42.9`（35 秒 / 18 条台词 / 5 簇 / AV 2 段 13,808 tokens）与
`08:29.6-08:59.6`（30 秒 / 17 条台词 / 5 簇 / AV 1 段 7,623 tokens / 62 秒）。

## 1. 类比，以及类比在哪里失效

借鉴的是本地化的术语表（termbase）流程：抽取候选术语 → 人工签核 → 翻译时由 QA 工具**强制**检查，
而不是叮嘱译者"请遵守术语表"。我们今天的形态恰好是后者：SKILL 写着"角色名只能来自
bible/manifest/台词"，但没有任何检查器兜底——所以它必然失败。

**相似的地方**（三条，都很实质）：

- 同实体多表出：`金发青年（青绿外套、左耳圈状耳环）` 与 `金发青年（深色上衣、浅蓝围裙）` 是同一个人，
  因为换装被写成两个字符串——这正是"同一个词前一段译成 A、后一段译成 B"的镜像。
- 专名必须有固定写法：茉里 / マリー / Marie，一个角色多种表面形式（中文字幕译名、日语原文、罗马音），
  需要别名映射而非强制统一字符串。注意别名**只收同一实体的不同写法**——本剧标题里的「菈菈 / Rara」
  与台词中被称呼的「茉里 / マリー」不是同一个名字，早期草稿把它们当别名合并过，那是错的。
- 一致性优先于正确性：术语表的价值一半在"就算错了也全篇一致"，因为不一致比一致更贵。

**失效的地方**（三条，必须写进设计，否则会高估这套东西）：

1. **术语是符号对符号，身份是符号对一段音频+一段画面。** 翻译里术语的 referent 由文本自身确定；
   这里"这个声音是谁"没有文本答案，只有证据。所以表能规定**写法**，永远不能规定**归属**。
2. **术语表可以全量预建，演员表不能。** 一部番的角色随集数出现，表必然增量生长，所以"候选/签核/
   只读"的生命周期不是可选项，是核心机制。
3. **术语错的代价是一个词，演员归属错的代价是整场戏的戏剧关系。** 所以强制检查的粒度必须落在
   "说话人"这一列上，而不是只落在"名字写法"上。

## 2. 架构：证据生产者 / 唯一判定处 / 消费方

```
证据生产者（只出证据，绝不写结论）
  speaker_diarize.py   → 簇 + 语音窗 + 声学属性(性别/年龄带/音线)        ← 新增字段
  av_understand.py     → 视觉锚点 + 每条动作带 mouth_state（≤3 秒窗口）    ← 新增通道，近零成本
  按簇分段拼接视频探测  → 静音 + 彩色分隔条，一次调用覆盖整集争议簇        ← 实测唯一可行形态
  字幕文本（本地）     → 呼语证据："茉里 你交朋友了" ⇒ 茉里是被称呼者    ← 新增，零成本
  外部资料（人工触发） → 实体清单与正确写法（不是归属！见 §5）
        ↓
resolve_cast.py（新增，唯一判定处）
  每族出候选分布 → 相乘合并 → argmax + margin；仍平票才弃权
  产出 cast.json：实体表 + 每簇的候选归属 + 证据链 + 状态
        ↓ 人工签核（一次）
materials/cast.approved.json（系列级，只读）
        ↓
消费方
  build_scene_manifest → 把 approved 表塞进每场证据包，并附"本簇未定名"标记
  写作者              → 只能引用表内标签；表外专名 = 致命
  splice_screenplay   → 强制检查 + 把 named/candidate/unknown 分布写进保真报告
```

关键约束：**判定层不产生新证据，只在证据上收敛**；任何一层想改归属，都必须留下可回溯的理由。

## 3. `cast.json` schema（草案）

```json
{
  "schema": "vts-cast/v1",
  "series": "再见菈菈",
  "entities": [{
    "id": "C1",
    "canonical_name": "茉里",
    "status": "approved",
    "aliases": ["マリー", "Marie"],
    "gender": "female",
    "age_band": "teen",
    "visual_anchors": [{"desc": "黑发齐刘海，白色上衣", "first_seen_ms": 340000}],
    "visual_label": "黑发齐刘海少女",
    "voice_profile": {"gender": "female", "age_band": "teen", "timbre": "bright"},
    "evidence": [{"kind": "subtitle_address", "line": 7, "note": "被『茉里 你交朋友了』称呼"}],
    "approved_by": "human", "approved_at": "2026-09-19"
  }],
  "slots": [{
    "slot_id": "S1",
    "profile": {"gender": "male", "age_band": "young_adult", "visual": "金发、青绿外套/浅色围裙、左耳环"},
    "coverage": {"clips_total": 6, "clips_visual_usable": 4, "clips_positive": 2},
    "status": "candidate",
    "entity_id": null
  }],
  "clusters": [{
    "cluster_id": "SPEAKER_A1",
    "assignment": {"candidates": {"S1": 3, "S2": 1}, "slot_id": "S1", "margin": 0.50,
                   "families_supporting": ["acoustic", "visual"],
                   "basis": ["acoustic.gender=male", "visual.mouth=2 of 6 clips",
                             "address_terms=none"]},
    "speech_ms": 11090, "line_count": 6
  }],
  "pending": [{"entity_id": "C7", "reason": "第 3 集新出现，未签核"}]
}
```

> **`visual_label` 是 AV 证据与实体之间唯一的合法桥**（落地时新增，本条早期草稿没有）：AV pass 的 prompt 被禁止输出真名，只能给描述性称呼（"金发青年"），所以视觉正证据按**称呼**计数；要把这堆证据接到某个实体上，必须由人在签核时显式绑定这个称呼。用字符串相似度去猜桥，等于把命名权从后门放回去。

设计要点：

- **槽位与命名是两层**：`slots` 是机器收敛出的"角色画像"（性别/年龄带/外观/覆盖率），
  `entities` 是人签核的"叫什么"。`clusters → slot` 由证据决定，`slot → entity` 由人决定。
  机器**永不**直接产出名字（强制点见 §6 第 3 行）。
- `visual_anchors` / `profile.visual` 是**多条**（换装、不同镜头）。
- `assignment.candidates` 是**分布**（每个槽位的支持计数），不是单一判决；
  `margin = (top1 - top2) / Σcandidates`，示例里 (3-1)/4 = 0.50——**阈值不预设，见 §11**。
  `families_supporting` 必填；`coverage` 记录视觉证据的可用片段比例——
  缺数据与信号弱是两件事，必须分开记（见 §7）。
- `status` 只有 `approved | candidate | unknown` 三态，**没有"默认相信模型"这一态**。

## 4. 生命周期

1. **提取**：每集跑完证据生产者后，`resolve_cast.py` 输出/更新 `cast.json`；新**槽位**一律进 `pending`
   （槽位是机器给的，实体只能由人给）。
2. **签核**：人看候选表（含证据链与 margin），批准或改名。这是**唯一**的常态人工环节（§5 的联网校正
   是可选的第二次人工介入）。
3. **合并**：`cast.approved.json` 是系列级只读文件；新一集只能追加 `pending`，**绝不覆盖已签核条目**
   （术语事故的经典成因就是后一集悄悄改了前一集的定名）。
4. **复用**：后续集数直接加载 approved 表；只有 approved 表里没有的簇才需要人再看一次。

### 4.1 槽位匹配优先级（第 4 步"复用"的算法，必须先定再写代码）

"次集零操作"和"新槽位一律进 pending"这两句话单独看都对，放在一起没有答案：新一集来的簇，
到底并进已有槽位（零操作）还是新建 pending 槽位（必然打断用户）？不定顺序，实现要么每集都问，
要么自动合并过松把错名扩散到全季。所以顺序**写死**为三级，逐级降级：

| 级 | 动作 | 允许条件（全部满足） | 结果 |
| :--- | :--- | :--- | :--- |
| **①** | 簇 → **已签核槽位**（entity 已定名） | 只用**正证据**重叠：声学属性两侧都已知且相容；视觉正证据至少 1 条指向同一锚点；且**至少两个证据族**同时支持；margin 不低于 §11 阈值 | 自动沿用，零操作，`cast.json` 记 `matched_via: "approved_slot"` 与所用证据 |
| **②** | 簇 → **未定名槽位**（pending） | 同上（只是 entity 还没名字，不影响连续性判断） | 自动归并计数，槽位仍 pending，签核时一并问 |
| **③** | **新建槽位** | ①② 都不满足，或两候选槽位得分之差在阈值内（含糊） | 进 `pending`，按 §4.5 轮次问用户 |

三条硬限定，否则修这个洞会引入它本想避免的事故：

- **只用正证据重叠。** §7 实测规则是视觉证据**单边有效**（没看到 ≠ 不是他）。若把"这一集没拍到该锚点"
  算成反对，等于把覆盖率当反证——那正是我们记 `not_observed` 要防的事。缺数据只降低支持计数，
  **永远不产生负分**。
- **单族不得自动合并。** 只有声学相容（同为"青年男声"）而视觉无证据时，本素材里两个人共享同一性别
  年龄带是常态——按单族合并会稳定地把该并的与不该并的一起并掉。与 §3 `families_supporting` 的约束同源。
- **含糊即新建，不猜。** ①② 的最高分与次高分之差低于阈值时走 ③。宁可多问一次，也不要把
  两个角色并成一个——过度合并是**不可逆**的（后续所有集都沿用错名），多问一次只是成本。

`matched_via` 与当时的分布快照必须留在 `cast.json` 里：审计"这一集为什么没问我"只看这一个字段。

## 4.5 用户旅程与签核界面（产品视角）

**价值主张一句话**：把"认出这是谁"（需要世界知识，难）改写成"从这 2-3 个候选里挑一个"
（看一眼片段就会）。机器负责举证，人只做选择题——这也是 §7 实测的直接结论：口型证据给的是
"黑发 vs 红发"，不是答案。

### 用户会遇到的三个时刻

| 时刻 | 用户动作 | 成本 | 触发点 |
| :--- | :--- | :--- | :--- |
| **首集签核** | 对每个槽位从候选里挑一个（或填正名）、确认别名、删掉机器虚构的"角色" | 5-10 分钟，一次性 | 阶段 3.7 之后、阶段 4 之前的检查点 |
| **后续集** | 通常零操作；只有 `pending` 非空时看 1-2 条新槽位 | <1 分钟 | 同上，`pending` 为空则不问 |
| **纠错** | 显式改 approved 表（见下"撤销与重跑"） | 按需 | 用户主动 |

### 引导点（不能让用户自己想起来）

阶段 3.7 跑完后，agent **必须**报一句并等回答：

> 本集识别出 N 个说话人：已定名 x 个（沿用系列演员表）、新候选 y 个、无法判定 z 个。
> 现在定名，还是先出草稿（成稿会标注"演员表未核验"）？

`pending` 为空时不问，直接继续——避免每集都被打断。

### 签核界面的形态（明确选定，不留给实现去猜）

**不做**：让用户编辑 JSON（引号逗号地狱，且改错一个字符整表失效）。
**做**：agent 打印一张 Markdown 表，用户用**自然语言**回一句，脚本解析后写盘并回显确认。

```
| 槽位 | 画像（机器给的证据）                     | 候选                 |
| :--- | :--------------------------------------- | :------------------- |
| S1   | 青年男声；6 段中 4 段可见正脸；2 段动嘴     | 金发青年 / 戴眼镜男人 |
| S2   | 老年女声；呼语"奶奶"被他人使用 3 次         | 奶奶                 |
| S3   | 系统音："Wi-Fiに接続しました"               | （无候选，建议标 系统音）|

用户回："S1 金发青年就叫托德，S2 对，S3 保持描述标签"
→ 脚本写 approved，并回显 diff 让用户确认一次
```

规则：**按轮次问，一轮最多 4 个槽位，问完问"还有 n 个，继续吗？"**
（"一次问 4 个、其余保持 `unknown` 走 `--draft`"这个写法是错的：实测 35 秒切片就有 5 个簇，
去切分后仍是 2-3 个槽位，首集签核若封顶 4 个意味着**第一次就有一半名字没定**，
把常态路径变成了降级路径。上限存在的理由是"一屏读得完"，不是"只许问一轮"。）
用户随时可以说"剩下的先跳过"，此时剩余槽位才进 `unknown` + `--draft` 语义。

**自然语言回话必须有失败路径**（否则解析失败就是隐形失败，正是本仓库反复出问题的类型）：

| 输入情形 | 处置 |
| :--- | :--- |
| 明确对应到槽位 + 候选（"S1 就叫托德"） | 写盘 + 回显 diff 确认 |
| 提到表里没有的名字，且无候选支撑 | **不写**，回问一句"托德不在本集候选里，确认新建实体？"——人名只能由人给，脚本不猜 |
| 指代不清（"第二个叫托德"） | 回显解析出的 `slot_id` 让人确认，不按位置推断 |
| 完全解析不出（回话与槽位无关） | 原样打印候选表 + 给一个**行内可改的最小模板**（`S1=托德 S2=奶奶 S3=跳过`），不静默跳过、不部分写入 |
| 用户对 diff 回"不对" | 整轮回滚，`cast.approved.json` 不产生半条记录（写盘走原子替换，沿用既有做法） |

### 撤销与重跑范围

approved 表带 `version` 与历史（每次签核追加一条，不原地改）。改表时脚本必须回答：
**"这个槽位已被用于第 2、5 集的成稿；这两份稿子需要重跑阶段 4-5。"** 依据是 `.cache` 里留存的
`cast.json` 快照（每集存一份当时用的表版本）——没有这个快照就无法回答，所以它是必需字段而非可选。

### 系列目录（新概念，必须先定）

现状核查：`workspace.py` **完全不碰 bible.json**——不生成模板、不查找系列配置、不复制。
而 SKILL 写着"配置一次、全季通用"。**这是一个没有实现的承诺**：用户实际要每集手工拷一份
`materials/bible.json`。演员表若沿用同一位置，会继承同样的缺陷。

所以 v0.6 要引入真正的系列级目录，并把已有的系列级配置一起搬进去：

```
<系列根>/                       ← 用户创建，例：~/番剧/再见菈菈/
├── cast.approved.json          ← 签核后的演员表（只读，带版本）
├── op_ed_windows.json          ← 从 bible.json 搬来：全季通用的窗口配置
└── episodes/
    └── ep02/                   ← 现有工作区（materials/ .cache/ output/）
        └── .v2s-series         ← 指回系列根（或 init 时 --series <路径> 写入）
```

- `workspace.py init --series <路径>`：绑定并**快照**当时的 approved 表进工作区（保证可复现）。
- 未绑定系列时：行为与今天一致（表为空 → 全部走 `--draft` 标注），不报错。
- 兼容：`materials/bible.json` 仍可读（旧工作区不破），但 SKILL 里"全季通用"那句话
  **在实现完成前必须改掉**，否则又是一处文档与产物不符。
- `op_ed_windows` 一并搬过去：它本来就是系列级配置，放每集是历史遗留。

## 5. 联网校正的边界（硬规定）

外部资料（官方 cast、Bangumi、维基）**只能**校正：实体是否存在、正确写法、别名集合、性别/年龄的
先验。**绝不能**用于：判断"哪个簇是哪个人"。理由：官方表给不出时间轴证据，用它做归属等于把
"我瞎猜"换成"带权威感地瞎猜"，比现在更危险。

流程上：由 agent 检索、**人确认**后写入，脚本内不做任何自动抓取。这是新增的外发面，必须进
`SECURITY.md` 与 `config_spec.py` 的声明体系（外部文本进上下文的位置越少越好——我们已经把屏显
文字按不可信输入处理了）。

## 6. 强制检查清单（逐条落到实现位置）

| 检查 | 级别 | 位置 |
| :--- | :--- | :--- |
| 说话人名不在 approved 表及其别名内 | **致命** | `splice_screenplay.py` lint |
| 说话人标签与本句呼语相同（自相矛盾） | `text_subtitle` 族**负证据**，进综合判定；不单独致命 | `resolve_cast.py` |
| **呼语被用作"这句话是谁说的"的正证据**（含 §4.5 表格里"因被称呼而定名"的写法） | **致命**：实现里禁止这条边 | `resolve_cast.py` 证据消费层（见 §7 呼语条目） |
| 说话人标签**溯源不到一个经人签核的 `slot → entity` 记录**（哪怕名字恰好在表里） | **致命** | `resolve_cast.py` 写盘前校验 + `splice_screenplay.py` lint |
| 写作者改判了 `cast.json` 的槽位归属但草稿无留痕注释 | **致命** | `splice_screenplay.py` lint |
| **某条台词的说话人标签**指向 `unknown` 槽位却写成了专名 | **致命**（只管标签，不管台词正文——见下） | `splice_screenplay.py` lint |
| 合并后分布仍平票（margin 低于阈值）却给出归属 | **致命**（应弃权） | `resolve_cast.py` |
| 两个簇的视觉正证据指向同一人（疑似过度切分） | 告警 + 保真报告列明，作为分离层审计信号 | `resolve_cast.py` |
| 簇被自动并进已签核槽位，但 `matched_via` 记录的证据不足两族 | **致命** | `resolve_cast.py`（§4.1 ①） |
| `cast.approved.json` 被本集内容改动 | **致命** | `resolve_cast.py` 写盘前校验 |

**两条"级别对但字面太宽"的限定**（评审指出，属实质缺陷）：

- 第 5 行原写"存在 `unknown` 槽位却出现了专名"——按字面理解会把**台词正文**里的人名一起判死。
  台词说"托德来了"是完全合法的（文本层的人名由字幕原文保证，本来就不归命名权威管）；
  致命只针对 **`DIALOGUE_HEAD_RE` 抓到的说话人标签**。实现时必须以标签为作用域，
  测试要给一条反例：正文含表外专名 → 不得报错。
- 第 4 行原写"机器把槽位直接写成专名（无签核记录）"——只查"有没有签核记录"会漏掉
  "名字碰巧在表里，但**这个槽位**从没有人映射到它"。检查对象必须是**这条标签的溯源链**：
  标签 → 槽位 → `approved_by: "human"` 的那条映射记录，缺一环即致命。

**已实测到的 lint 反向偏置（必须先修，否则新制度会被它带偏）**：
**更正一处事实错误**——本早期草稿写"描述性标签白名单只有一条正则
`^[^（）]{1,12}(的声音|之声)$`（`splice_screenplay.py` 的 `DESCRIPTIVE_SPEAKER_RE`）"，实际是**两条**：
`GENERIC_SPEAKERS` 集合（同文件，行号会漂故不给，一项角色/亲属/旁白/通用声线词清单，含"奶奶""姐姐""旁白"，v0.6 P1 又补了"女声""男声"）
与 `DESCRIPTIVE_SPEAKER_RE` 正则（只管「…的声音」「…之声」这类结构化描述）。
下面这个实测现象是**两条一起**造成的：写作者一个专名都没编，
仍被告警 `关西腔者, 女声, 系统音`，而「威严的声音」「唤茉里的声音」放行——**同样描述性、
证据强度甚至更高（系统音是最硬的一条），待遇相反**。后果是它会诱导写作者去挑**更长**的标签而不是
**更有证据**的标签。

修法：判定方向反过来——**非专名结构的描述标签一律放行，只有疑似专名才要求溯源**。

> **⚠️ 本条草稿版本（含评审后补的"有界集合"式）方向是反的，P1 落地时才发现并改掉。**
> 曾写成 `疑似专名 = 标签 ∈ (approved ∪ 别名 ∪ 本集呼语表)`。问题是：**一个杜撰的名字
> 按定义不在这三个清单里**（清单只收已知的），于是它不被判为疑似专名 → 不要求溯源 →
> **制度最想拦的那类错误被直接放行**。"有界"这个要求本身没错（评审举的"奶奶/姐姐每集
> 都在字幕里出现"是真问题），但边界必须画在**描述性形状**这一侧，不能画在**已知名字**
> 那一侧——已知清单是用来"通过"的，不是用来"识别嫌疑"的。

实际落地规则（`scripts/speaker_labels.py`，P1）：

```
放行 = 标签 ∈ GENERIC_SPEAKERS（通用称谓/旁白/声线词，永不要求溯源）
     ∪ 标签形状是描述性：DESCRIPTIVE_SPEAKER_RE（…的声音|…之声）
                      ∪ DESCRIPTIVE_SHAPE_RE（≥2 字词干 + 角色/年龄/声线后缀）
                      ∪ 带括号限定（路人（男））
其余（名字形状） = 必须溯源到 approved 表 / 别名 / bible / manifest 的已知表面形式
```

- **`GENERIC_SPEAKERS` 的处置**（不留给实现去猜）：继续作为放行清单，但语义收窄为
  "通用称谓，永不要求溯源、也永不作为命名候选的唯一依据"。P1 补了 `女声` `男声`
  （实测的假阳性案例），并把整个清单从 `splice_screenplay.py` 移到 `speaker_labels.py`
  ——lint 与 resolver 必须共用同一个"什么算名字"的定义，否则两边判定会分叉。
- **词干须 ≥2 字是有意的代价**：「凉音」这种以描述性后缀结尾**的真名**会被判为需溯源。
  方向上宁可多查一次表（查到就放行），也不让编造的名字免检。
- **描述性标签不再消失，改为被计数**：成稿的保真报告新增一行
  "可溯源 x 个 / 描述性（未定名）y 个 / 表外专名 z 个"。放行描述 ≠ 假装没看见描述——
  一集里 y 很大就是演员表没做完的信号，这正是 §13 弃权率要看的东西。
- **致命只在有表可查时生效**：绑定了系列且 approved 表非空 → 表外专名退出码 9；
  未绑定 → 维持告警并写明"无表可对照"（`--draft` 语义，见 §8）。一道满足不了的闸门
  只会让人绕开整个流程。

拼装器统计条数写进保真报告，让"写作者推翻机器"不再是隐形动作。落地形态比本节早先的一句话更具体：

- **检测的是逐条台词，不是逐个标签**。血缘闸门（§6 第 4 行）只能说"这个标签溯源到了**某个**签核实体"，

  或簇**无定名**却写了任何专名（第 6 行），即违例。

## 7. 证据通道的新增与一处历史遗留

- **声学属性**（性别/年龄带/音线）：在**已付费的同一次分离调用**里多问几个字段，零额外调用。
  未知值一律 `unknown`，禁止兜底猜测。
  **三者都是闭合枚举**（`gender: male|female|unknown`；`age_band: child|teen|young_adult|adult|
  elderly|unknown`；`timbre: bright|sharp|deep|low|hoarse|soft|nasal|robotic|unknown`），
  不是自由文本——早期草稿里写的"音线：明亮偏尖"那种描述跨 part 做多数票**永远不收敛**，
  等于白问。簇级按 ≥60% 已知票取胜，`unknown` 票不进分母（缺数据不是反对票，同 §7 视觉族规则），
  并随簇输出 `*_support`（如 `3/4 turns`）与顶层 `acoustic_attribute_compliance`
  （模型到底有多少条真的答了）——**提示词是否生效要有数，不假设**。
- **视觉说话（ASD）是"单边证据"：说了就算，沉默不算否证。**（本条结论来自 ep02 第二段的四次实测，
  见下方"实测记录"。）要问的不是"口型对不对得上这个音"（音素级同步，番剧确实失效），而是
  "这个人的嘴在连续画面里有没有反复开合"。实测性质：**高精度、低召回**——它点名某人动嘴时基本可信
  （静默负对照 2 段 0 假阳性、系统音段正确判"无人"），但 17 个语音片段里只有 6 个给出正证据（35%）。
  因此规则是：**正例计入候选集；缺失一律记 `not_observed`，绝不允许当成"不是他"的否证。**
- **它的正确用法是缩小候选集，不是选出唯一答案。** 这是本设计早前写错、后被纠正的一点：曾按
  "argmax + margin，平票即弃权"来消费这个信号，那等于把它最有价值的部分扔掉——某簇拿到
  "黑发×1、红发×1"的平票，信息量不是 0，而是**把候选从"全剧若干人"压到 2 个**。
  所以各族证据的输出必须是**候选分布（每个人一个支持计数）**，不是单一判决；
  联合判定 = 各族分布相乘后再看 argmax 与 margin，**只有合并后仍平票才弃权**。
- **相乘的前提是各分布同基，这一条以前没写。** 各族证据的基数天然不等：`acoustic` 覆盖全部 17 条，
  `visual` 只有 6 条有正证据（实测 35%）。直接拿计数相乘等于让"被观测得多"的族独裁。规则（符号，
  **不含任何预设数值**，权重仍按 §11.7 待测）：

  ```
  对每一族 f：  p_f(x) = n_f(x) / (Σ_y n_f(y) + u_f)     # u_f = 该族未观测的窗口数
  权重：        w_f    = confidence_f × families_valid_f  # 单族支持时 w 退化，不虚高
  合并：        score(x) = Π_f p_f(x)^w_f                 # 几何加权，等价于对数域线性相加
  弃权：        margin = (top1 - top2) / Σ_x score(x) < 阈值 →  abstain
  ```

  - **`not_observed` 进分母不进分子**：未观测让该族的分布整体变平（削弱它的判别力），
    而不是给某个候选投反对票。这是"缺数据 ≠ 信号弱"这条规则在算式里的落点。
  - **全零族必须剔除**：某族在该窗口一条证据都没有（`Σ n = 0`）时不参与相乘，
    否则 `p = 0/(0+u)` 会把所有候选一起打成 0，`margin` 变成 0/0。
  - 示例形状（结构示意，数值为占位非实测）：
    `acoustic: {S1: 3, S2: 1}`, `visual: {S1: 1, S2: 1, not_observed: 4}` →
    S1 与 S2 在视觉族**同为 1**，视觉不改变排序，只把候选从"全部槽位"压到 {S1, S2}；
    最终排序由声学决定，视觉的作用是**收紧候选集**并触发过切分审计。
- **附带用途：反向审计分离层。** 若两个不同簇的正证据都指向同一个人（本次 A3 与 A4 都拿到"黑发"），
  这是**声学过度切分**的信号——本素材 4 个人类簇对 2 个可见人物，本来就可疑。
  所以口型证据不只用来"簇→人"，也用来检查"这几个簇是不是本来就该并成一个"。
  （注意方向：过切分可以这样发现；**欠切分发现不了**，因为一个人对应多个簇才是异常，
  一个簇对应多人是正常现象——同簇里本来就可能有多句不同听者插话。）
- **限制是覆盖率，不是可靠性**。听者反应镜头、背影、画外音、远景小脸拿不到视觉证据——这是**缺数据**，
  不是**信号弱**：前者如实记 `unknown` 并统计 `coverage`，后者才需要降权。两者混为一谈会让"没看到"
  被误读成"不是他"。实测的覆盖率就是 35%（17 个语音片段仅 6 个给出正证据），所以 `coverage` 是这个
  族的**一等公民字段**：没有覆盖的片段必须显式存在，不能当成零票。
- **边界精度有限**：循环嘴型给不出 ±0.1s 的起止，所以视觉证据只在 **≥1 秒**的窗口上生效，不做逐字对齐。
- **口型证据只能由模型给，自建 CV 仪器这条路不成立**（本条是撤回先前设计后的结论）。曾经写过"主仪器用
  嘴部 ROI 帧差 + 面内配准 + 张口度 + 周期性"三层方案，经质疑后判定不可行，理由记在这里以免有人再走：
  ① haarcascade 一类真人脸检测器对动画脸（大眼、几乎无鼻、嘴是一条描线）命中率过低；
  ② "嘴是暗腔、取暗区纵向跨度"这个前提**在动画上是假的**——动画嘴常是白牙块或描线，前提错则全链错；
  ③ 真要做得靠深度模型（TalkNet / Light-ASD 一类），直接违反本插件"纯标准库 + 可选 numpy/opencv"的底线。
  所以**不引入任何自建口型仪器**；模型是唯一能给出这个信号的仪器。
- **可审计性靠留帧，不靠算分**：每条口型结论都保留"当时喂给模型的那几张帧图"在 `.cache` 里，
  人和 agent 都能回放核对。这比一个帧差分数（0.37 到底是嘴动还是筷子？没人说得清）强得多。
  实测反例就是本素材第一段：`0.0-3.5s 金发青年右手持筷…张口将食物送入口中咀嚼`——嘴部区域像素剧变，
  但那是吃饭不是说话。
- **采集粒度：按台词，不按场次。** 实测证据（ep02 第二段 30 秒）：AV 自发给出了
  `7.0-18.0s 黑发短发者…嘴唇开合`，说明信号在模型能力内；但这条 11 秒窗口里含 **5 条语音、分属
  A3 与 A4 两个簇**，对"A3 还是 A4"没有判别力。所以口型证据必须以**每条台词的窗口**为单位采集。

### 实测记录（ep02 第二段 08:29.6-08:59.6，17 条语音 + 2 段静默负对照）

| 探测 | 输入 | 调用 | 结果 |
| :--- | :--- | :--- | :--- |
| 静帧 3 张/窗 ×2 次 | 57 张图分 19 组 | 1 次 | 正证据 5 与 6 个窗口，**同输入两次不一致**（窗 8 翻转） |
| 静帧 7 张/窗 | 133 张图 | 1 次 | 正证据 5 个——**加密度没有用** |
| 拼接短视频 5fps（按窗口分段） | 38.5s 无声视频 + 洋红分隔条 | 1 次 24k tokens | 正证据 10/17 |
| **按簇分段（彩色分隔条 + 静音）** | 19 片段 / 6 部段 | 1 次 18.6k tokens、约 2 分钟 | 见下 |

按簇分段的干净结果（控制组修正后）：

```
A1 系统音(1 片段)  → 无人动嘴 ✓            A4 (2) → 黑发×1
A2 (4)            → 红发×1，2 段看不清      A5 (3) → 黑发×1、红发×1（平票）
A3 (6)            → 黑发×1、红发×1（平票）   静默负对照(2) → 无人动嘴 ✓  ← 0 假阳性
```

**复现配方**（三处都是踩过的坑）：① 本机 ffmpeg **没有 drawtext**、也没有 pillow，所以窗口边界靠
**纯色分隔条**标记，不靠烧字；② 必须**去掉音轨**，否则模型能靠听到的声音作弊，测的就不是视觉；
③ **负对照要严格落在静默空档内，且不加 padding**——本次第一版控制窗是 `空档中点 ±700ms` 再 ±200ms，
结果两头都压上了真实语音，导致我一度得出"精确率下降"的**错误结论**（已撤回）。
经验：**控制组不干净比没有控制组更糟**，它会给出方向相反的自信结论。

**成本结构**：`completion_tokens 8,459` 里 **8,295 是 reasoning**，真正的 JSON 输出只有 164。
这类判断的开销**被模型的思考主导，不是被输出主导**——按输出 token 估成本会严重低估。
调用次数才是墙钟成本：一次问一批（19 窗口 / 2 分钟）远好于逐条问（17 次 / 10-17 分钟）。

- **短台词直接丢**：动画嘴是循环的，0.4 秒可能刚好落在闭合帧上（本次数据里就有 400ms 的 turn）。
  用它当"嘴没动"的证据是**假阴性陷阱**；阈值取 **≥0.5s**，且按台词时长加权。
- **样本要跨镜头**：同一机位里的多条台词**不是独立观测**——那个镜头认错人，几条一起错。
  镜头边界 `scene_detect` 已给出，直接复用。
- **上面的数字只有 19 个片段，不足以定阈值**。要定 `candidate → approved` 的门，需要人工标 20-30 个
  窗口做真值、跑 k≥3 次看稳定性，再算精确率/召回率。先前版本里"单次准确率按 0.85 估"那句话
  **是我编的，已撤回**——阈值必须来自测量，不来自本文档。
- **`source_type` 决定权重**：`anime | live_action | dub`。真人向 ASD 更强（真音素同步可用），
  权重自动上调——本插件要扩展到真人，这套不能为番剧特化。
- **证据族内不叠票**（否则置信度系统性虚高）：`acoustic` / `visual` / `text_native`（原声转写）/
  `text_subtitle`（字幕译文）/ `external`。同一次 AV 调用同时给的"他在画面里"和"他的嘴在动"是
  **一票不是两票**；日语原声的"俺"与中文译文的呼语是同一源文本的两种呈现，也不算两票。
  `margin` 之外还要卡 `families_supporting` 的最少族数：只有单一族支持的结论最多是 `candidate`。
- **呼语（vocative）= 指向听话人、绝不指向说话人。这条边在实现里必须只存在两个方向**：
  1. **负证据**："说话人标签 == 本句呼语"是自相矛盾，进 `text_subtitle` 族的综合判定
     （不单独致命：真出现"角色念自己名字"时会被其他族压过去，不需要豁免开关）。
  2. **命名证据**：别人反复用某称谓称呼这个**槽位**（听者画像与说话画像相符时），
     可以给该槽位提供 `entity` 命名候选——§4.5 表格 S2 那一行属于此类。
  - **禁止的方向（致命）**：拿呼语当"**这句话是谁说的**"的正证据。画外有人喊"茉里！"、
     镜头里茉里正听着，朴素规则会把这句话归给茉里——**这正是本设计起点上我实际犯过的错**
     （ep02 场 1：把被称呼者当成了说话人，真值是金发青年）。所以证据消费层要显式声明
     `subtitle_address` 族的 `role` 字段只能取 `naming` 或 `negative`，出现 `attribution` 即拒绝写盘。
- **视觉锚点归一**：跨窗口稳定 ID，是共现统计的前置条件（没有它，§3 的矩阵根本对不齐）。
- **跨语言 `text_agreement` 处置**：本素材音轨是日语原声、字幕是中文译文，实测 `text_agreement: null`。
  跨语言的文本相似度不是"低"而是**无意义**，必须显式降级为 `not_applicable`，不能留 null 让人误读。
- **视觉证据必须能取 `unknown`**：番剧大量听者特写、背影、画外音（本次 AV 笔记就有"背对镜头站在窗前
  水槽边"），这些窗口按 `coverage` 记为"未覆盖"，而不是记为"不是他"。

## 7.5 端到端实测（2026-09-20，第一次真跑；本文档首次有真数字）

素材：ep02 `06:07.9-06:42.9` 实切 35 秒（1920→480p 重编码、日语音轨 a:0、内封简中字幕重基线）
→ 18 条字幕 / 6 物理镜头 / 6 宏场景 / `qwen3.8-omni-flash`。

**花费与墙钟**（进 §11.6 的预算表）：声学 1 片 **32 秒墙钟**；AV **6 段 = 20,135 tokens / 191 秒墙钟**
（≈每段 32 秒、每 35 秒素材 5.7k tokens/段）。即 **AV pass 的墙钟约为片长的 5.5 倍**——
比本文档先前按"探测形态"估的数更贵，因为这里是逐场景全量理解而非争议对复核。

**P0 声学属性遵从率 = 18/18 = 1.00**（三个字段每条都答了，且都是合法枚举值）。
簇级聚合支持度也是满票（如 A1 `male 6/6`、`teen 6/6`、`bright 6/6`），
5 簇画像互不相同 → **闭合枚举这条路成立**，且比预想更稳。

**P3 `mouth_state` 遵从率 = 1.00，但窗口 ≤3 秒遵从率 = 0.778（4/18 超标）→ 门（0.80）不过 → 信道自动降级**。
`resolve_cast` 实测确实拒绝使用视觉族（`visual_family_available: false`、5 簇全弃权）。
超标的 4 条是 6.5s / 3.8s / 3.5s / 3.5s——模型倾向把一段连续动作写成一个窗口，而不是拆开。

**真跑抓到的两个设计级问题（不跑就不会知道）**：

1. **`moving` 混淆"说话"与"咀嚼"**。本段是早饭戏，10 条 `moving` 里至少 5 条原文就是吃东西
   （「腮部起伏，持续咀嚼」「张口含向筷尖」）。按现在的定义这些会被当成"他在说话"的正证据——
   **高精度低召回的前提在一部吃饭戏里直接破了**。修法不是调阈值，是加一个同一次调用内的字段
   `mouth_motion: speaking|chewing|yawning|other`，只有 `speaking` 计正证据。
   在此之前 §11.7（视觉族权重）**无从测起**：信道上混着语义不同的两类事件。
2. **视觉锚点不稳定，量化了**：同一场景模型给出 6 种不同描述
   （"金发侧脸青年（蓝绿衬衫、耳垂双耳环）"／"金发蓝绿外套青年"／"系头巾戴眼镜的金发男子"…），
   其中至少两个指同一人。所以 §7 说的"视觉锚点归一是共现统计的前置条件"不是修辞——
   **不能拿自由文本称呼当锚点 ID**。当前设计里锚点由人签核时的 `visual_label` 提供，
   签核界面把每簇的原始画像列表摊给人看，正是为了让人一次把同人的写法归并掉。

**结构性事实（不是缺陷，但必须写下来）**：**首集**没有演员表 → pending 槽位没有 `visual_label`，
视觉族结构上无法投票；呼语族同理（名字清单为空，`address_terms` 为空）。
于是 §4.1 的"至少两族"在首集**必然**导致 100% 弃权——这是制度顺序而不是模型不行：**首集就是必须问人**，
第二集起才有自动沿用。本次实测的表就是"5 簇 5 问、0 自动"，与推导一致。

**第二次真跑（同一段素材，加了 `mouth_motion` 之后，实测对照）**：

| 量 | 第一次 | 第二次 |
| :--- | :--- | :--- |
| `mouth_state` 合法率 | 1.00 | 1.00 |

| P3 门（0.80） | 不过 → 信道降级 | **过 → `usable: true`** |
| 12/10 条 `moving` 的成因 | 混着咀嚼 | **`speaking` 7 / `chewing` 2 / `other` 3**（模型还把"夹菜送入口"判成 `other` 而非 `speaking`） |

→ **§11.7 的视觉族权重现在终于有东西可测了**：信道上不再混语义不同的两类事件。
计数只认 `moving + speaking`。

**次集复用（真实证据 + 模拟上一集已签核的表）实测**：5 簇中 **2 簇自动沿用**（`acoustic`+`visual` 两族一致，
margin 0.5 / 1.0，不打断用户），**3 簇仍问人**；弃权率 0.6。
其中 A4 弃权但**候选集保留** `{S3: 0.5, S4: 0.5}`——"是这两个之一"正是这条信道值钱的输出。
**§7 预言的过切分审计真的开火了**：A1 与 A3 的视觉正证据同时命中"穿绿色毛衣、戴眼镜的卷发男子"，
文档里的 `over_split_suspects` 第一次拿到真实案例（不是编的）。

**顺手修掉的实现偏差**：视觉正证据原先按称呼在全片计数，而不是按簇的语音窗取画面
（你当初的原话是"把 a 说话的时间轴对应的画面抽出来只评估 a"）。已改为时间求交，
并让签核表显示"这一簇说话期间谁在动嘴"。**第二次真跑又抓到这一版的实现漏洞**：
`by_cluster.get(cid)` 对"该簇毫无重叠"返回 `None`，被当成"回退到全片计数"，
于是两个全程画外/背对的簇继承了别人的正证据（实测 A4/A5 各拿到 金发青年×2）。
现已规定：**无重叠 = 空分布**，只有 v3 之前的旧产物才允许走全局回退。

**第三段真跑（另一段素材，验上面那组数不是过拟合）**：ep02 `09:18.2-09:48.2`（30 秒 / 15 条台词 /
13 镜头 / **8 宏场景** / 4 声学簇）。

| 量 | 结果 |
| :--- | :--- |
| P0 属性遵从率 | **15/15 = 1.00**（4 簇画像互不相同：女/成年/低、女/少年/柔、男/成年/沉、男/孩童/亮） |
| P3 `mouth_state` 合法率 | 1.00 |
| P3 窗口 ≤3 秒遵从率 | **0.944**，`usable: true` → 上一段加的措辞在新素材上也成立，不是过拟合 |
| 呼语信道 | **第一次真正生效**：`菈菈×1`、`茉里×1` → 说出这两句的簇各被排除一个身份（`not_speaker`），不做任何认定 |
| 过切分审计 | **真开火**：A1 与 A2 的语音窗里同一张脸（红发校服少女）都在说话 |
| 端到端成稿 | 15/15 台词逐字回填、8 场、0 告警，头部与附录如实写"未核验 / 弃权率 100% / 疑似过度切分 1 组" |
| 花费 | 声学 1 片 **47 秒墙钟**；AV 8 段计划 → 7 段实跑 = **30,524 tokens / 384 秒 + 续跑一段**；
  覆盖率 `covered_avg 87.5%`（那 0.5 秒场景按缺口显示，不再是死锁） |

这一段抓到三个缺陷（都已修 + 加测试）：

1. **0.5 秒的宏场景会把整条 AV pass 永久卡死**：DP 在这个窗口切出一个 0.5 秒的宏场景，
   转码出 62 KB 的片段，上游直接 `bad_request (400)` → `run` 每轮都 exit 7，
   也就是**一个没人能被问到的场景，让 7 个已完成场景的成果永远交付不了**。
   修法不是放宽失败语义，是不去问：加 `AV_MIN_SEGMENT_SEC = 1.5`，低于下限的场景进
   `skipped_too_short` 并在 stderr 点名，覆盖率把它显示成缺口（写作者回退关键帧证据）。
2. **过切分审计原先只在"签核后的槽位"上算**，于是首集（没有表时）恰好看不见它——而那正是
   过切分最要命的时刻。信号本身不需要名字（两个簇共享同一张脸就够了），已改成按**原始视觉画像**算。
3. 一个**成稿丢行**的拼接 bug（`A + B if cond else C + D` 的优先级）：有 `cast.json` 时
   "说话人标签构成"整行被吃掉。没有测试断言那一行，所以它躲过了 317 条测试。
   现在附录由列表拼装，正反例都有测试。

## 8. `--draft` 降级语义

不签核也能出稿，但**必须留下看得见的痕迹**，否则用户会把它当定稿发出去：

- 成稿元数据头加一行：`演员表：未核验（N 个说话人槽位为候选，M 个未定名）`。
- 保真报告里逐个列出未定名槽位及其画像，方便事后补签。
- 说话人一律用描述性标签（不出现候选专名）——**降级不等于放开猜测**，这正是本次翻车的形态。
- 理由：没有降级通道，人就会为了省事绕过流程，表反而形同虚设。

   `not_speaker` 过滤，并在表格里写明"不是 茉里——这簇台词里在叫他们"。

每步都要有前后对照证据（同一段素材、改前改后各跑一次），沿用本仓库既有做法。

## 11. 未决问题（需要拍板）

1. ~~呼语冲突判致命会不会误伤"角色念自己名字"？~~ **已决**：不判致命，改为 `text_subtitle` 族的
   负证据进综合判定（§6、§7），真出现自我称呼时会被其他族压过去，不需要豁免开关。
2. 声学属性要不要含 `emotion`？（倾向：不含——对槽位收敛无帮助，且增加模型输出漂移面）
3. ~~自动归属在什么阈值下允许直接写进成稿？~~ **已决**：`clusters → slots`（身份连续性）可由机器按阈值
   自动合并；`slots → entities`（命名）**永不**自动，必须人签核（§3、§6）。
   **补决（评审指出这里是半截决策）**：只说"按阈值"没有答案，合并的**顺序**与**允许条件**见 §4.1 三级表；
   仍**未决**的是阈值数值本身——它是 §11.6/§11.7 要测的量，不预设。
4. approved 表放系列目录还是每集工作区？（倾向：系列目录 + 工作区只读快照，保证可复现）
5. ~~嘴部 ROI 定位怎么做~~ **已决（方向作废）**：不自建口型仪器，见 §7 的撤回说明。
6. ~~帧数/密度怎么选~~ **已实测**：静帧 3→7 张灵敏度不涨（5/17→5/17），**换成会动的短视频才有效**
   （10/17）；但同输入两次静帧结果不一致，说明需要 k≥3 重复。仍未决的是**重复次数 k 与预算**：
   整集按"每簇一段拼接视频"估 ≈ 5-6 次调用/30 秒素材，且 reasoning token 主导成本
   （实测一次 18.6k 中 8.3k 是思考），P3 之前要给出去噪后的预算数。
7. **新增**：35% 覆盖率下，视觉族该给多大权重？它点名时可信，但三分之二的时间沉默——
   权重给高了会把"没拍到"当成反对，给低了等于没有这一族。需要扩样后定，不预设。
  **2026-09-20 真跑后追加前置条件**：`mouth_state` 现在把"说话"与"咀嚼"混在一起（§7.5），
  在此之上算权重没有意义。先加 `mouth_motion` 分类、再谈权重。

## 12. 明确不做

不做**音素级**口型同步（SyncNet / LSE-D 那类，番剧无效，且我们要的是 ASD 而非它）；**不自建任何 CV
口型仪器**（haarcascade 对动画脸失效、"嘴=暗腔"前提在动画上不成立、深度模型又违反依赖底线）；
不引入 torch 级依赖（保持"纯标准库 + 可选 numpy/opencv"）；不让脚本自动联网抓资料；
不用外部 cast 决定归属；不让机器把槽位直接写成专名；不在表里存任何凭据。

## 13. 怎样算 v0.6 做完了（验收标准）

写代码之前先把"完成"定义清楚，否则又会变成"功能加了但制度没落地"。

**必须能演示的四个场景**（用 ep02 这两段素材跑，逐条有前后对照）：

1. **首集签核**：跑完阶段 3.7 → agent 打印候选表 → 用户回一句话 → approved 表落盘，
   且表里每个名字都能回查到证据与当时的帧图。
2. **次集复用**：同一系列第二集跑起来，`pending` 为空时**不打断用户**，说话人自动沿用表；
   出现新槽位时只问新槽位。
3. **强制生效**：故意在草稿里写一个表外专名 → splice **退出码非 0 并点名**（不再是告警）；
   故意让说话人标签等于本句呼语 → 综合判定里该归属被压下去或弃权。
4. **降级诚实**：不签核直接出稿 → 成稿头部与保真报告都写明"未核验 + N 个槽位未定名"，
   且正文里**没有**任何未经表支持的专名。

**必须量出来的两个数**（不达标就不算完成，不写进代码当默认值）：

- 视觉族在本素材上的**精确率/召回率**（人工标 ≥20 个窗口做真值，k≥3 次重复看稳定性）。
- 合并后**弃权率**：如果 >50% 的说话人槽位仍要弃权，说明这套证据不足以支撑制度，
  要回头降低承诺（比如只做"候选提示"不做"自动归属"），而不是硬调阈值。
- **P3 提示词遵从率**（评审指出这条原本是隐形假设）：AV 输出里 `mouth_state` 取到三值之一的条目占比，
  以及动作窗口 ≤3 秒的占比。二者低于 80% 则视觉通道按 §10 P3 降级，不进入 P4 的相乘。

**必须全绿的回归**：既有 211 条测试不破；新增测试覆盖 §6 表格里每一条致命项（致命项没有测试
就等于没有闸门）；`cast.approved.json` 被改动、表外专名、呼语冲突三种情况各有反例测试。
